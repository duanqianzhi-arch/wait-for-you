# 1.2.4 桌面组件尺寸修复

当前最新公开试用版：[1.2.5](1.2.5-public-beta.md)，新增固定更新流程和网页版导入；以下保留原测试交付记录。

日期：2026-10-09；versionCode：10。独立安卓测试版，正式网站保持1.0.1。

## 原因与修复

用户已确认原先失败的同学成功导入两页课表，底部保留两门未排定课程。新的截图显示周组件外框很高，课表只占上半部分；今日组件只显示上午两次课程，底部提示“还有2次课程”，而下午和晚上的课程在周组件中可见。因此本次不是课程丢失，而是显示容量与桌面实际尺寸不一致。

旧代码总是用OPTION_APPWIDGET_MIN_HEIGHT计算行高及今日课程容量。桌面可能同时提供横屏最小高度与竖屏最大高度，用最小值绘制高组件会留下空白，并过早隐藏今日课程。

- Android12及以后优先采用桌面提供的精确尺寸列表，为每个支持的尺寸生成布局，由桌面选择。列表为空、无效或过多时回退到尺寸范围。
- 兼容旧桌面的横竖屏范围：竖屏使用最小宽度与最大高度，横屏使用最大宽度与最小高度；调整组件大小时重新布局。
- 周组件的第1—13节按对应高度展开，今日组件按同一高度计算能展示的课程数量。确实放不下时仍提示剩余数量；未识别安排提示保留。
- 每个尺寸布局都有刷新入口，原有动态内容清除、课程点击、本地修改和日期高亮逻辑保留。

实现参照[Android官方组件尺寸文档](https://developer.android.com/develop/ui/views/appwidgets/layouts)。本次没有取得这台荣耀桌面的实际尺寸参数，因此框架复现证明代码中的缺陷，新布局仍需用户手机验收。

## 手机测试

[1.2.4测试下载页](https://personal-timetable.henu-study.pages.dev/android-update.html?versionCode=9)。直接覆盖安装，**不要卸载原应用**；无需重新导入课表。设置里的检查更新仍查看正式网站，测试版升级使用此独立链接。

1. 确认设置显示1.2.4，原课表、手动修改、收藏保留。
2. 点周组件右上角刷新，确认课表展开至第13节，组件下半部分不再大片空白。
3. 点今日组件刷新。在仍有四次课程的早晨、组件空间足够时，应能同时看到上午、下午和晚上的课程；已结束的课仍按原逻辑不再展示。
4. 拉高、缩短组件，检查显示容量随尺寸改变；刷新三次不重复课程和节次，只有今日高亮。
5. 若桌面仍缓存旧布局，仅移除并重新添加组件，不卸载App、不删除课表。

线上／未排定课程没有具体星期节次，继续放在App周表底部，不伪造时间塞进周网格或今日课程。
