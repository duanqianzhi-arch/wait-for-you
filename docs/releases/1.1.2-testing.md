# 1.1.2 登录后自动读取修复测试

日期：2026-10-08。版本 1.1.2 / versionCode 5，原包名与签名保持。独立测试站为 https://personal-timetable.henu-study.pages.dev/ ，正式站仍为 1.0.1。

## 原因和修复

用户确认 1.1.1 能登录，但停在有功能菜单的教务首页。经用户自行登录后的只读网页核查：外层保持 `/frame/homes.action`；沿“教学安排”菜单打开课表时，框架链是 `frmDesk → frame_1 → frmReport`，分别为教学菜单、个人课表、列表报告。直接把个人课表地址加载为顶层页面，会被学校转到 `/frame/errors/405.jsp`，提示访问受限或无效。本次只保存结构与统计，不保存学生身份、真实参数或私人课表。

旧代码在首页整页结束时直接跳个人课表 URL，解析器只支持个人页→报告的短链；手动点菜单后外层仍是首页，原生 URL 检查也会拒绝结果。Android 的 `onPageFinished` 只针对主框架，不能依赖它观察子框架的后续切换。[官方回调说明](https://developer.android.com/reference/android/webkit/WebViewClient#onPageFinished(android.webkit.WebView,%20java.lang.String))。

本版沿学校已验证的 `S203/教学安排` 菜单执行只读导航，保留原首页和学校产生的子框架地址；遍历严格限定的首页→S203 菜单→个人课表→列表报告链，自动选择列表后提取。原生使用页面可见/结束事件启动有界轮询，显示打开菜单、切换列表和等待课表等状态。等待最多约 40 秒，单次脚本回调最多 10 秒；重试保护导航代号，超时或跳走后的回调不会生成导入。仍没有学校网页原生桥，不放行外站、HTTP、错误证书或任意 iframe。

## 手机测试

1. 从测试站下载 1.1.2 APK，直接覆盖安装，不卸载旧版。确认设置显示 **1.1.2**，原教室收藏还在。
2. 我的课表→从教务系统导入→在学校原网页登录。程序应显示“已登录，正在打开…”等进度，自动进入教学安排并读取完整课表。
3. 等待导入确认页，核对课程，再确认保存。若学校页面加载慢，可等约 40 秒；失败后在原生顶部点“重试”，不要重复提交账号密码。
4. 如果仍停住，反馈顶部提示文字、停留页面类型与 1.1.2 版本号；截图遮住学号、姓名和私人内容即可。
5. 继续 [完整功能测试](1.1.0-testing.md#测试顺序)：切周、空地点、编辑重开、重新同步、取消与删除。周课表基于整学期周次数据计算，不必每周重新导入。

App 内“检查更新”仍检查正式站；测试更新请直接使用独立测试链接。喜鹊儿的周视图可用于人工核对结果，本版没有接入其账号或接口。

## 验证范围

21 项安卓框架测试、11 项 Node/产物脚本及同签名 release/androidTest 构建通过。实际 APK 已核对包名、code5、原签名、仅 INTERNET 权限及 22 个网页资源；大小与哈希见 `android-release.json`。

匿名完整框架链、菜单只点击一次、手机侧栏折叠、列表切换、错误菜单来源拒绝、无主页面结束事件时继续读取、跳走与超时回调丢弃等回归测试已加入。完整链、原生首页 URL 检查和直接跳转问题先失败、修复后通过；移除超时回调保护的临时验证也被测试捕获，保护已恢复。原首次短链、字段白名单、完整性与教学周校验继续保留。

电脑端已观察到沿菜单可展示本学期课表；这不等于新 APK 真机完整导入已通过。本机真实 WebView 设备测试仍无可用设备，手机覆盖安装、读取、清理和持久保存继续等待用户验收。桌面组件和通知仍未实现。
