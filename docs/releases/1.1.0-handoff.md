## 已完成与验证

- 学校原网页登录后只读提取最小课程字段，预览确认保存；不采集密码、学号、姓名、教师和完整学校 URL。
- 本学期周次解析、周课表、课程详情、修改和恢复、重新同步与切换另一份课表；底部三项、顶部保留原样。
- 安卓私有 AtomicFile 保存课表，原收藏键不变。部分写入失败回滚，取消和解析失败保留旧记录。
- 独立审查发现四个重要问题并已修复：失败重试保留导入模式和选择、残缺表格行拒绝、保留本地安排时另存学校最新基表、清理失败在下次导入前重试。每项均有失败→通过的匿名回归测试；审查未提出轻微待改项。
- 十一个前端/产物脚本、十五项安卓框架测试、签名构建与实际包内资源核对通过。APK 有 22 个网页资源，仅声明 INTERNET 权限。签名指纹沿用 1.0.1，具体 SHA-256 与字节数见 `dist/downloads/android-release.json`。

## 实现取舍及影响

1. 使用隔离 Git 工作区，应用的工作区工具不适用原历史非 Git 目录；后续需从 Git 工作区继续，不要改个人归档副本。
2. Windows 环境用 PowerShell 保存计划进度和测试证据；续做需核对 ledger 和提交，不能把记忆中的“开始”当成尚未实现。
3. 未识别时段保留为 `pendingSchedules`，不猜上课时间；这些安排暂不放入周网格，用户可在详情查原文字。
4. 本机用与 Wrapper 相同版本的现成 Gradle 8.11.1 及缓存，避免下载超时；其他开发者仍可用标准 Wrapper，需要自己的 SDK/JDK。
5. 没有连接真实手机，先交付测试包；自动测试不能证明学校 WebView 登录、所有存储清理或手机覆盖更新有效。
6. 严格 JSON 校验独立为 `TimetableSchema`；后续改数据结构要同步 Java 与 JavaScript 校验。
7. 同一字段同时变化、安排移动/拆分或删课时要求明确选择。保留原安排会标为本地保留，用户需要核对学校更新。
8. `localOnly` 课程另存有界的 `schoolRecord`：最新学校课程，或代表学校删除的 null。恢复整门课采用它，避免恢复旧时间；额外字段仍受私有 JSON 大小和字段限制。
9. 测试下载和正式发布分开；真机通过前不合并发布、不替换正式下载。已有发布目标授权用于推送候选分支及建立草稿 PR，保留工作区等待反馈。

## 接下来

先按 [安卓测试说明](1.1.0-testing.md) 验证。失败时只收集机型、Android/WebView 版本、操作和错误文字；不要索取密码、Cookie、完整个人 URL 或私人课表。若学校结构改变，先用匿名化结构复现，再改适配器；不要扩大到任意网站或忽略 SSL 错误。

测试通过后：同步最终 APK、metadata、版本页、README → 跑完整前端测试和安卓构建 → 核对包名/版本/签名/权限/哈希 → 合并候选分支 → 部署正式 `dist` → 核对正式 HTTPS 下载哈希。若再次发测试升级包，需要递增 versionCode，避免同版代码引起安装和更新判断混淆。

下一阶段才设计桌面组件与消息通知：先考虑今日课程/下一节课组件，和用户主动开启的上课/学习提醒。它们应读取同一份个人课表和本地修正，不另存密码，不以“无课”直接决定用户应学习或休息。当前没有这些功能的按钮、原生代码或通知权限。

可供下一位维护者直接使用的任务说明：

> 继续等你下课项目 `feat/personal-timetable` 的 1.1.0 真机验收。先读 README、docs/releases/1.1.0-testing.md、此交接和已批准设计/计划。保留同一包名、签名、收藏键及私有课表，不把用户凭据或真实课表写入 Git。检查当前 Git 状态和 APK metadata，按用户实测修复失败路径并重跑现有测试；未完成真机验收前保持正式网站旧版。课表通过后再设计安卓桌面组件和用户自选通知，顶部不变，底部仍为自习/我的课表/设置。
