# 个人课表：自动导入与本地修改

日期：2026-10-08。状态：用户已审阅并确认“符合，按这份设计继续”；正在编写实施计划，未开始产品实现、构建或发布。

审阅重点：先做安卓“学校原网页登录 → 自动识别整学期 → 预览确认保存 → 周课表与本地修改”；底部三项、顶部保持原样；再次同步保护修改。桌面组件、学习提醒和后台无人值守同步另行实施。手动文件导入不作为主要流程。

## 目标与已确认要求

用户希望同学首次使用时，登录本人教务系统即可自动得到个人课表；逐门录入或手动选择文件不能成为主要导入流程。导入后可以修改教室等信息，继续使用现有找自习教室功能。界面沿用黑白手绘便签和咖喱狗。

底部为“自习 / 我的课表 / 设置”；顶部品牌、校区切换及现有自习流程保持原样。校区切换控制找教室与收藏，不过滤个人课表：跨校区的本人课程仍显示。

本设计聚焦第一阶段：安卓自动导入、周课表、编辑、重新同步保护修改。桌面组件和学习通知在后续阶段使用同一份数据，本阶段不新增它们。

“自动导入”定义为用户登录后由程序识别并解析课表，无需逐门录入或导出文件；不等同于首次免登录、代解验证码或永久无人值守登录。用户确认预览后才替换本机课表。

## 已有项目与现场依据

主源码 `D:/wait-for-you-github`；检查起点提交 `7ea74c9`，开始检查时工作区干净。现有网页是原生 HTML/CSS/JavaScript 与 Hash 路由；安卓是 Java Activity + WebViewAssetLoader 的包内网页。现有 `MainActivity` 阻止包外资源，Manifest 没有网络权限，不能直接拿这个主 WebView 加载教务网站。

2026-10-08，用户在浏览器自行登录河南大学教务系统，授权继续查看个人课表。只读观察到：

- HTTPS 入口 `https://xk.henu.edu.cn/cas/login.action`，页面标明正常情况下免验证码；不能据此保证每次登录无需验证码。
- 导航“教学安排”到个人课表；个人课表框架路径 `/student/xkjg.wdkb.jsp?menucode=S20301`。
- 列表报告框架路径 `/wsxk/xkjg.ckdgxsxdkchj_data10319.jsp`。实际 URL 带个人相关参数；不保存这些参数、个人页整页 HTML、截图或登录凭据到仓库。
- 外层 `frmDesk`，个人课表子框架 `frame_1`，报告框架 `frmReport`。框架名只作为当前适配辅助，必须结合 HTTPS 域名、路径和列头判断，不能仅凭名字读取任意框架。
- 可见列包括“上课班级代码”“课程”“选课状态”“上课时间地点”。表头有 12 列，数据行另外有 4 个隐藏单元格，不能把全部单元格盲目拼成课程。
- 多条时间地点用中文或英文分号分隔；结构例子用虚构名称表示：`1-18周 三[3-5] 示例教学楼5404(96)`；有的段落没有地点。
- 当前列表统计为 10 门、13 条安排；临时只读格式检查识别了全部 13 条，其中 8 条地点为空。此检查不保存课程内容，不代表安卓导入已完成，也不覆盖未在样本中出现的单双周等格式。

原作者 MIT 开源项目 HENU_Assistant 的路径与现场吻合，可借鉴路径与表格处理思路；对本项目应自行实现严格周次与编辑合并规则。研究证据见 [自动导入研究](../../research/2026-10-08-henu-auto-import.md)，引用或采用任何实际源码须保留版权声明与许可。

## 方案选择

推荐本机专用教务浏览器：用户直接向学校网页输入登录信息，程序从当前本人课表页面读取最少课程字段，解析和保存均在手机完成。无开发者代理后台。

文件导入虽然容易验证，但不符合本次主要体验，因此不作为本阶段主要入口。集中收集账号密码的服务器方案增加凭据管理与维护成本，本阶段不采用。未来若学校提供面向第三方的官方授权接口，再单独评估迁移，不假设当前 CAS 登录路径等同 OAuth。

## 使用流程

1. 点击“我的课表”。没有数据时显示简洁空态与“从教务系统导入”，不是一张伪造的示例课表。
2. 首次说明：在学校原网页登录；不保存密码；读取课程、周次、节次和地点；课表保存在本机。进入独立教务浏览器，顶部显示精确学校域名及关闭操作。
3. 用户自行输入账号、密码并处理学校要求的验证。App 不填写或记录这些输入，不绕过认证。
4. 检测登录后进入已验证的个人课表页面；显示加载进度。不能凭出现任意表格就认为成功。
5. 页面完整加载后自动解析，显示本机预览：学期、课程门数、安排条数、待补地点与识别失败提示。用户可以返回学校页面重试；不要求复制或选择文件。
6. 点“保存课表”后原子替换当前课表，回到周视图。取消或失败不改变旧课表。仅导入单个学期，现阶段先适配已验证的 2026—2027 第一学期；其他学期校历需核实后扩展。
7. 周视图默认当前教学周，左右切换、点击“本周”恢复；点击课程查看详情与“修改”。每次打开按北京时间重新计算周次，课程内容不需要每周重导入。
8. 修改课程名、地点、备注、星期、节次或周次，保存时校验；可“恢复学校记录”。修改只作用于本机课表，不提交学校。
9. 页面提供“重新同步”。登录失效时重新走本人登录流程；预览显示新增、变更与删除，保留本地修正。另设“替换为另一份课表”操作，明确提示清除旧修正后才能替换，避免切换账号时误套修改。

## 模块边界

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| `TimetableImportActivity` | 学校网页导航、页面识别、读取回调、错误提示 | 只接受已验证学校 HTTPS 来源；不给学校网页挂应用存储桥 |
| `henu-schedule-adapter.js` | 在已确认的课表文档中提取最小字段 | 随 APK 提供；不读取密码框、Cookie、整个页面 HTML 或学生身份栏 |
| `personal-timetable.js` | 周次/节次标准化、周视图数据、差异与修改合并 | 无 DOM 依赖；使用虚构数据测试，不依赖学校网络 |
| `TimetableStore` | 保存基表与修改，版本迁移、原子写入、删除 | App 私有存储；留出后续原生组件读取接口 |
| 本机页面通信 | 包内页面读取/保存课表、启动导入 | 仅允许包内精确来源与主框架，消息类型与长度校验；教务页面无此能力 |
| `app.js` / `styles.css` / `index.html` | 第三导航项、周课表、详情与编辑交互 | 不改教室无课判断与收藏存储键 |

安卓课表持久存储以原生 `TimetableStore` 为唯一正本，便于后续桌面组件使用；网页内仅保留运行时视图和未提交编辑状态，不把教务登录会话塞入现有 localStorage。普通网页版受跨来源限制，不能宣称与安卓一样可读教务页面；在课表空态明确引导使用支持该能力的安卓版本，不放点击无效的导入按钮。本阶段不承诺网页版与安卓间的课表同步。

## 页面读取与输入校验

- 用表头名称定位课程、上课班级代码、选课状态、上课时间地点，不依赖固定第 10 列的唯一假设；拒绝缺列或重复歧义列的表。
- 读取“选中”的本人课程，课程前缀编码只用于稳定识别；不存学号、姓名、学生班级或教师信息。上课班级代码用于识别教学组，不采集上课班级名称。
- 正确拆分一门课程的多个周次/地点段，不把多个时间拼成一节。
- 周次标准化为明确整数集合；覆盖连续范围、单周、双周和离散周组合。不认识的格式必须报告，禁止默认为全学期。
- 星期范围 1—7；常规节次 1—13，使用已经确认的开封作息。不同学校校区作息和中午单节不能猜测，遇到未覆盖格式提示补正并禁止伪造标准时段。
- 没有地点时存空值，显示“地点未填写”，仍保留上课时段。地点中的座位容量原文可保留，不当作教室空位；不能自动把个人地点修正写入教室公共数据库。
- 无时间的课程保留为“待完善”，不在周网格中编造占位；用户须在预览明确看到待完善条目，才能保存其余数据。
- 设总数据大小上限 512 KiB、最多 500 门/2000 条安排；字段长度课程名 120、地点 240、备注 1000 字。对页面文字以纯文本渲染，HTML 与脚本不得进入应用模板。
- 不可识别的部分与空课表明确区分。没有识别到预期课表结构、或导入条数与页面统计不符时，不能用零门课程覆盖旧数据。
- 网页课程声明的门数与提取数核对；分页若出现，必须确认已经完整取得或明确提示未完成，不能只保存第一页并宣布全量成功。

## 数据与重新同步

课表正本包含 schemaVersion、学校、学期、学期第一周周一、最大教学周、北京时间时区、导入时间、适配器版本、学校课程基表和本地修改。

每门课程以学期、课程编码、上课班级代码组成稳定键。一个课程下有多个安排，每个安排有星期、周次集合、开始/结束节次、地点。学校提供稳定安排 ID 时优先使用；当前仅验证页面文本，因此不假设存在此 ID。

本地修改按课程和安排字段存储。重新导入时用稳定课程键先匹配，安排再用星期/节次/周次匹配；一对一明确匹配才能自动应用旧修正。若学校改动了整个时段、一个安排拆成多个或出现歧义，预览显示冲突，由用户选“保留我的修改 / 使用学校更新”；不凭行号或课程标题强行套用。

在校端删除了本地修改过的安排时，提示“学校已移除”，选择随校删除或保留为本地安排。导入新的课表与更新现有课表是两个明确选择；导入新学期不会跨学期套旧修正。

保存成功前不更新界面上的“最后同步”。磁盘写入失败保留旧正本并显示提示。重新打开、后台返回或覆盖安装后都从正本重新加载。

## 原生边界与登录会话

主 App WebView 继续只加载包内资源。教务专用 WebView 允许联网，Manifest 增加正常网络权限；不额外请求通讯录、位置或文件权限。

导入浏览器和 App 视图的逻辑职责分开；两个 WebView 不是天然独立的 Cookie 容器。学校会话由 WebView 处理，不能声称“没有自己保存密码，所以设备不存在会话”。首版导入结束或取消后清理教务浏览数据，不提供记住密码开关；每次重新同步可能需再登录。后续持久会话需单独设计与确认。

仅校验 HTTPS、精确 `xk.henu.edu.cn`、正确端口与无 userinfo，结合已经验证的个人课表路径执行读取；不使用简单字符串前缀、通配域名或任意用户 URL。若统一认证涉及其他学校域名，必须先观察并核实正式来源后才加入，不对外部页面自动解析。

教务网页不注册 `addJavascriptInterface`。由原生在正确页面执行随包提供的只读提取脚本，通过 `evaluateJavascript` 的回调接收最小 JSON；发起和回调时检查当前 URL 与导航代号，防止页面已跳走仍写入。同源报告框架需逐层验证；异源框架不绕过浏览器隔离。

不忽略 SSL 错误、不允许混合内容、不开放 file/content URL；下载与不相关跳转受控。正式包关闭 WebView 调试，不输出课程内容、Cookie、密码、完整个人 URL 到日志或崩溃报告。

首版沿用现有进程，不为单个导入功能增加多进程或提升最低系统版本。导入开始前及完成/取消后清理本应用 WebView Cookie；此操作是应用 WebView 范围的，不是学校域专属，但现有包内主页面不使用 Cookie 登录。缓存清理只影响可重载资源。学校 WebStorage 仅按实际访问并核验的学校 origin 调用 `deleteOrigin`，该 API 文档限定于 Web SQL，不能宣称它清除了所有 HTML5 数据。学校文档的 localStorage/sessionStorage 由原生在核验来源后执行定向清空；清理失败需记录不含个人数据的错误并在下次导入重试。绝不调用 `deleteAllData` 或删除 `appassets.androidplatform.net` 的数据，以避免误删原收藏与偏好。

Cookie 清理回调完成前不得开始新的导入；杀进程中断后，下次导入启动首先清理残留会话。需验证 Android 8+ 设备的实际行为，不能把两个 WebView 说成彼此存储隔离，也不承诺彻底擦除全部 WebView 存储痕迹。学校若改用 IndexedDB 等保存可复用认证数据，应先完成相应定向清理再开放该接入方式；本次没有读取或验证这些隐藏存储。

个人课表放 App 私有文件，维持 `allowBackup=false`。初版不持久化凭据或会话、不上传课表，因此不引入服务器或密钥管理服务。隐私说明需随发布更新，清楚描述本机课表读取、保存、修改及删除。

## 失败与恢复

| 情况 | 行为 |
| --- | --- |
| 未登录、会话失效或验证码 | 展示学校原页面由本人完成；不后台循环试密码 |
| 没网、网站维护、SSL 错误 | 明确失败，保留上次已保存课表 |
| 页面加载中、框架延迟 | 有限等待与手动重试，不持续无上限轮询 |
| 页面结构变化或缺列 | 说明适配失败，旧课表仍可看可改 |
| 空地点/无时间/未知周次 | 标明需完善或识别问题，不虚构课程时段 |
| 重复导入/重复回调 | 同一导入请求只提交一次，相同基表不产生重复课程 |
| 切换账号或学期 | 预览确认替换对象；不给另一份课表自动套用原修正 |
| 旋转、返回、杀进程 | 未提交导入不影响旧正本；重开可继续查看旧数据 |

## 验收与发布条件

第一阶段必须在用户真实安卓手机上完成首次登录自动导入。浏览器格式统计和虚构测试均不能代替这个验收。

1. 不逐门录入、不选择文件，完成学校登录后能得到完整本学期课程；当前已知样本应为 10 门、13 条，空地点 8 条明确标注。
2. 连续周、单双周、离散周、多段安排、未标地点与未知格式均有针对性测试；以合成匿名样本进入 Git，不包含真实学生表。
3. 周切换与日期周次、十三节作息正确；不出现把晚间课程放到下午的错误。
4. 修改地点、时段、周次后退出重开仍保留；恢复学校记录有效。
5. 重新同步不重复课程，保护无歧义的本地修正，歧义/删除正确显示待确认。
6. 未知来源、恶意 hostname、HTTP、重定向竞态、伪造课表 HTML、超长 JSON、XSS 字符串均不能调用保存能力或运行脚本。
7. 导入成功/取消/失败清理会话后，原收藏、偏好和旧课表仍在；覆盖安装保留存储正本。
8. 现有七个前端脚本与安卓包内资源/导航边界测试通过；新增测试同时覆盖导入浏览器边界和实际 native 存储读取。
9. 保持应用包名与签名，递增 versionCode，同步版本页、APK 下载与文档；尚未完成的功能不发布无效按钮。

需要先完成最小安卓导入验证，再实现最终周课表界面。若学校登录不支持 WebView、页面不可读或会话隔离在支持设备上不成立，应如实报告具体问题并调整方案，不能宣称已经支持自动导入。
