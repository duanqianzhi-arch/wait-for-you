# 手机课表与安卓桌面组件设计

日期：2026-10-08。状态：用户已确认“方案符合，两个组件都做”；实现与真机验收按对应plan推进。

## 用户目标与现状

用户反馈自动导入已经可用，但周课表边距大、仅能看到少数星期，连续两三节课程只出现在开始节的格子里，不能缩放，也没有桌面组件。此次目标是随时看清整周和下一节课，延续黑白手绘风格；顶部校区和底部“自习／我的课表／设置”保持已有结构。

现有 `weekly()` 将课程放在开始节的 `<td>` 中，既不跨行，又由长文本撑高整行；手机 CSS 强制表格至少 790px。个人课表唯一正本是 Android 私有 AtomicFile；尚无 AppWidgetProvider。

## 手机页面修正

- 默认适应可用屏幕宽度，完整显示七天。320、360、390、430px 手机与宽屏均检查；节次栏窄、网格细，减小课表标题和外边距。
- 每节高度固定，1–2节课程跨两行，3–5节跨三行，11–13节跨三行。课程内容不会把其他节次撑高。格子只显示课程名、简短地点；完整时间、地点和编辑仍在课程详情。
- 提供“缩小／放大／适应屏幕”，范围为适应屏幕的100%–220%；双指在课表内调整相同尺度，放大后可滑动。缩放只作用于课表。回到本周、切换校区和打开详情不会清除已导入数据。
- 同一日重叠课程并排显示；单格内容过长可截断，所有课程均可点击，完整课程名、节次和地点保留在无障碍名称及详情中，不静默漏课。
- 保留当前周、上一周／下一周／本周、待完善课程与同步保护规则。没有识别出的时间不绘成假课程。

## 推荐的桌面组件

提供两个可选组件，而不是把完整 App 缩成一个桌面窗口：

1. **今日课程**：默认4×2，可调整尺寸。显示日期、教学周、当前／下一节课的名称、时间和地点，空间足够时再列后续课程；超出空间显示剩余门数。未导入、今天无已排课程、课程全部结束、学期外和读取失败分别显示真实状态。存在未识别安排时提醒打开 App 核对，不能暗示确定无课。
2. **本周课表**：默认4×4，可拉大。七天与13节形成紧凑网格，课程按节次跨度排列；空间小只留课程名，地点在更大尺寸展示。重叠安排显示数量提示，点击进入 App 查看完整课表，不遮掉冲突。组件不提供双指缩放，尺寸由手机桌面的编辑操作调整。

App 的课表页面提供“添加桌面组件”，可选今日／本周。调用 Android 的固定组件接口，由桌面最终确认。接口返回支持并不代表用户已经添加成功，文案只能提示“请在桌面确认”。桌面不支持该接口时，显示“长按桌面空白处 → 添加小部件 → 等你下课”的路径。普通浏览器不显示安卓组件入口。

另一种方式是只做今日组件，工作量更小，但不能在桌面浏览整周；只做整周则占用桌面面积较大。推荐两种并存，用户自由选择。

## 数据、更新与原生边界

- 新增原生课表投影模块，读取同一 `TimetableStore`，按 Asia/Shanghai 与 firstMonday 算周次。先应用本地名称／地点／星期／节次／周次修改，再过滤当周课程；本地保留的旧安排参与展示，`schoolRecord` 仅用于恢复，不替换本地有效课表。
- JS 与 Java 投影以同一份匿名测试向量验证：单双周、周日、跨天、晚课、跨节、本地修改、学校移除后的保留、学期外和缺地点。原文件损坏时显示“请打开 App 检查”，不删原文件。
- 使用 Java AppWidgetProvider 和 RemoteViews，复用现有 Java 项目，不增加服务器或登录接口。两个 provider、各自布局和 provider-info 负责不同展示；共用投影与刷新服务函数。
- 保存／同步／修改／删除成功及打开 App 后主动刷新已有组件；失败保存不刷新成未保存的新数据。删除个人课表后组件清空课程文本。
- 使用系统允许的30分钟周期刷新和组件“刷新”按钮，显示实际更新日期／时间；跨日后按新日期重算。系统省电可能延迟周期刷新，不能承诺分钟级准确。打开 App 或点刷新可立即校正。首版不引入精确闹钟、持续后台服务或学习通知。
- 组件内容本来会交给手机桌面显示；不上传个人课表。组件点开仅用明确的 MainActivity Intent，进入个人课表；不接受任意外部网址／脚本。PendingIntent 明确目标并采用不可变标志，接收器只处理已知系统与自身操作，校验组件ID。
- 课表桥增加枚举化的组件请求，不向学校页面注册桥，不改变学校登录与清理范围。不新增密码存储。

## 风格与布局

白纸 `#FFFFFF`、应用纸底 `#F4F4F2`、墨黑 `#171717`、次要文字 `#666660`、格线 `#E5E5E1`。App 沿用手写字体；课表文字减小但保留可读行距，重要信息左对齐。组件使用系统可读字体，保留黑白边线与小咖喱狗标识。

```
我的课表             ← 第6周 → 本周
双指缩放       −  100%  +  适应屏幕
    一   二   三   四   五   六   日
 1  ┌────┐        ┌────┐
 2  │课程│        │课程│  ← 连续节次占满
 3  └────┘  ┌────┐└────┘
 4          │课程│
 ...
添加桌面组件          重新同步
```

## 验证与交付

前端验证跨节几何位置、重叠课程均可进入详情、缩放上下限／恢复、单指滑动与双指缩放不冲突；用匿名数据在真实浏览器检查手机尺寸。原生验证本地投影、各空态、尺寸变化、固定请求返回、更新／删除、明确 Intent 和数据来源；编译真实组件资源。

新包递增 versionCode，沿用签名覆盖安装，不要求卸载。独立测试下载沿用既有 Preview，正式网站／下载在手机验收前保持原版。真机需要检查：桌面选择器能找到两个组件、添加确认、拉大缩小、点击跳转、改课后的刷新、删除后的清空、隔天显示、覆盖安装保留收藏与个人课表。自动化框架通过不能代替小米桌面的实际测试。

## 一手资料

- [Android 组件概览](https://developer.android.com/develop/ui/views/appwidgets/overview)：组件应展示可快速浏览的信息，并响应桌面尺寸变化。
- [固定组件接口](https://developer.android.com/reference/android/appwidget/AppWidgetManager#requestPinAppWidget(android.content.ComponentName,%20android.os.Bundle,%20android.app.PendingIntent))：Android26起支持；由桌面决定是否确认，返回true不等于添加完成。
- [组件更新](https://developer.android.com/develop/ui/views/appwidgets/advanced)：系统周期至少30分钟，支持交互主动更新，受后台资源限制影响。
